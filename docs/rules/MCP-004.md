# MCP-004 — Malformed protocol framing

**Severity:** varies by kind · **Defined in:** `src/mcpscan/anomalies.py`

Framing violations observed on the wire during a live scan. The 2025-11-25 stdio
transport is deliberately thin — newline-delimited UTF-8 JSON, one message per
line, no embedded newlines, nothing on stdout that is not an MCP message — so
every entry here is a server departing from a very short list of rules.

**Severity varies per finding within this rule.** Several kinds here are hygiene
rather than attack, and saying so is the point: a report that ranked an npm
banner alongside a stack-exhaustion attempt would get skimmed, and the
exhaustion attempt would be what got missed.

Kinds marked *aggregated* produce at most one finding per scan carrying
`metadata.occurrences`. A chatty server emits hundreds of banner lines, and
hundreds of identical INFO findings is an unreadable report.

## embedded-newline

**medium / high confidence.** A literal newline inside a message split it into
two lines. The client sees two unparseable halves; rejoining them and reparsing
proves what happened.

Framing confusion is a primitive: what the client parses is not what the server
believes it sent, and a payload can be positioned to land on either side of the
split depending on who is reading.

**Fix:** JSON-escape newlines inside string values. `json.dumps` does this by
default; the violation usually means a message was assembled by hand.

## json-too-deep

**medium / high confidence.** Nesting deep enough to exhaust a recursive parser.

Worth knowing: in CPython `json.loads` raises `RecursionError`, not
`JSONDecodeError`, so a client with the obvious `except json.JSONDecodeError`
does not catch this and the exception escapes into whatever was reading the
stream. mcpscan counts bracket depth with a byte scan before parsing.

**Fix:** no legitimate MCP message is thousands of levels deep. Look at what is
generating it.

## oversized-line

**medium / medium confidence.** *Aggregated.* A message with no terminating
newline, large enough to exhaust a client reading a line at a time.

The stdio framing has no length prefix, so nothing bounds a message except the
client's own cap. Either an attack or a badly broken server — hence medium
confidence.

**Fix:** terminate every message with a newline and keep messages to a sane size.

## batch-array

**low / high confidence.** A top-level JSON array. JSON-RPC batching was removed
in revision 2025-06-18 and is not part of 2025-11-25.

Either a stale implementation or a probe for a client that still accepts the
older shape.

**Fix:** send one message per line.

## result-and-error

**low / high confidence.** A response carrying both `result` and `error`.

Two clients may resolve the ambiguity differently — one reads the result, one
reads the error — which makes it a place to hide behaviour that only shows up in
some consumers.

**Fix:** exactly one of the two, per JSON-RPC 2.0.

## bad-utf8

**low / high confidence.** *Aggregated.* Invalid UTF-8 on the protocol channel,
which the spec requires to be UTF-8. Encoding confusion changes what downstream
readers see.

**Fix:** encode output as UTF-8.

## non-json-stdout

**info / high confidence.** *Aggregated.* Non-MCP content on stdout: npm
deprecation banners, framework startup lines, progress bars, a stray `print()`.

**This is hygiene, not an attack**, and it is reported at INFO for that reason —
below the default `--fail-on high`, so it will not fail a build. It is still
reported, because stdout is the protocol channel and noise on it is where a
payload hides.

**Fix:** the spec reserves stderr for exactly this. Log there instead.

## missing-jsonrpc

**info / high confidence.** *Aggregated.* Messages without a correct
`"jsonrpc": "2.0"` field. Conformance sloppiness.

mcpscan still reads the message: refusing to would hand a server an opt-out from
inspection for the price of one wrong field.

## malformed-message

**info / medium confidence.** *Aggregated.* Messages that are not a well-formed
request, response or notification — no `method` and no `id`, a non-scalar `id`, a
response with neither `result` nor `error`.

Confidence is medium because the kind is a catch-all; ranking it higher would be
claiming more than the evidence supports.

## Remediation

Emit only newline-delimited JSON-RPC on stdout, one message per line, UTF-8, with
no embedded newlines. Logging and diagnostics belong on stderr, which the
2025-11-25 stdio transport reserves for exactly that.
